# 추억일지도 (memories-maybe) — 트리플 스타일 여행 플래너 (프로토타입)

일정 · 지도 · 가계부를 한 화면에서 관리하는 여행 플래너입니다. 첨부해주신 트리플 캡처 3장(발리
여행 DAY2 일정, 가계부, 지도)을 UI/UX 레퍼런스로 삼아 독자적으로 디자인했고, 이후 실제로
업로드해주신 트리플 CSV 원본(오키나와 여행, 39건)을 그대로 반영했습니다. 앱을 실행하면
샘플 여행이 **두 개** 들어있습니다 (`/trips`에서 전환 가능):

- **발리 여행**: 캡처 화면의 DAY2 일정 + 가계부 캡처에 보이던 실제 지출 5건
- **오키나와 여행**: 실제로 업로드해주신 CSV 39건을 그대로 파싱한 가계부 (일정 캡처는
  없었기 때문에 일정 탭은 비어 있습니다 — 임의로 지어내지 않았습니다)

## 최근 변경사항 (이번 업데이트)

- **저장 실패가 더 이상 조용히 넘어가지 않습니다.** 일정/메모/비용 추가·수정 시, 온라인
  공유 여행에서 서버 저장이 실패하면(네트워크 오류, 마이그레이션 미적용 등) 이제 화면에
  빨간색 에러 메시지가 뜨고 입력한 내용이 그대로 남아있어 다시 시도할 수 있습니다. 예전에는
  실패해도 창이 그냥 닫혀서 "분명 저장했는데 안 보인다"는 문제가 있었습니다.
- 로컬(브라우저 저장) 모드에서 `localStorage` 쓰기 자체가 막혀 있는 경우(아이폰 사파리의
  "모든 쿠키 차단" 설정, 비공개 모드 등)에도 화면 위에 빨간 안내 배너가 뜹니다.
- 장소 추가/수정 화면에서 위도·경도를 직접 입력하는 칸을 없앴습니다. 검색으로 고른 장소는
  좌표가 자동으로 들어가고, 직접 입력한 장소는 좌표 없이 저장되어 지도에는 안 뜨지만
  일정에는 정상적으로 남습니다.
- 아직 좌표가 있는 장소가 하나도 없는 지도의 초기 위치를 발리에서 **서울**로 바꿨습니다.
- **앱 이름을 `추억일지도`(영문 코드명 `memories-maybe`)로 다시 확정했습니다** — 이전
  이름이었던 `가보자GO`(`gabojago`)에서 바꿨습니다 (`triple-planner` → `gabojago` →
  `memories-maybe` 순서로 바뀐 것). 폴더/`package.json` 같은 코드상의 이름뿐 아니라,
  화면에 보이는 앱 이름(홈 화면 타이틀, 아이폰 홈 화면 추가 시 이름, PWA manifest)도 전부
  "추억일지도"로 바뀌었고, Cloudflare Worker 이름(`gabojago-api` → `memories-maybe-api`)과
  D1 데이터베이스 바인딩 이름(`gabojago-db` → `memories-maybe-db`)까지 전부 바꿨습니다.
  **단, Worker는 이름을 바꾸면 Cloudflare에서 완전히 새 서버로 배포되기 때문에, 새 주소로
  `NEXT_PUBLIC_API_BASE_URL`을 업데이트하고 재배포해야 합니다 — 자세한 순서는
  `worker/README-worker.md`의 "이미 gabojago-api로 배포해서 쓰고 계신 경우" 섹션을 꼭 먼저
  읽어주세요.** 브라우저에 저장된 로컬 여행 데이터의 키 이름도 `memories-maybe:*`로
  바꿨지만, 기존 `gabojago:*`와 그 이전의 `triple-planner:*` 키에 있던 데이터를 자동으로
  한 번 옮겨오도록 만들어서 데이터가 사라지지 않습니다.

## ⚠️ 먼저 알려드릴 점

1. **오키나와 CSV 관련 참고사항**
   - 실제 파일에는 데이터 39행 아래에 "▼ 통화별 금액", "▼ 총 금액" 같은 요약 섹션이
     붙어있었습니다. 최초 버전의 CSV 파서는 이 요약 줄까지 지출로 잘못 인식하는 버그가
     있어서, 헤더와 컬럼 수가 다른 행(요약 줄)과 "▼"로 시작하는 행을 자동으로 걸러내도록
     `src/lib/csv.ts`를 수정했습니다. 실제로 전체 코드에서 이 CSV를 다시 파싱해
     **39건 · 합계 ₩1,965,060** (CSV 파일 자체의 "총 금액" 행과 정확히 일치)을 확인했습니다.
   - 이 CSV의 "결제한 사람"과 "나눠 낼 사람"이 매 행 동일 인물 1명이라, 실제로는 각자
     자기 몫을 각자 결제한 여행입니다. 그래서 정산 탭에는 송금할 금액이 0으로 나옵니다 —
     버그가 아니라 데이터상 서로 나눠 낼 비용이 없기 때문입니다.
   - CSV에 실제 달력 날짜가 없고 "여행준비/1일차/2일차/3일차"만 있어 여행 기간은
     2025-11-01~11-03(3일)로 임의 설정했습니다. 여행관리 화면에서 바로 수정할 수 있습니다.
   - 최초 발리 트립 관련 안내: 말씀하신 "44건 CSV"의 원본 파일은 처음엔 첨부되지 않았고
     (이미지 3장만 첨부됨) 가계부 캡처에 보이던 5건만 반영했었는데, 이번에 실제 CSV
     (오키나와, 39건)를 보내주셔서 그대로 반영했습니다. 발리 CSV 원본도 주시면 동일하게
     반영해드릴 수 있습니다.
2. **이 작업환경(샌드박스)의 네트워크 제한으로 `npm install`을 직접 실행해 보지 못했습니다.**
   이 세션은 보안 정책상 npm 레지스트리(registry.npmjs.org)에 접근이 차단되어 있어
   패키지를 설치·실행하며 검증할 수 없었습니다. 대신 (a) Next.js 표준 구성을 그대로 따르고
   (b) 의존성을 next/react/react-dom/typescript/tailwind 등 핵심 패키지로만 최소화했으며
   (c) 전역에 설치된 TypeScript 컴파일러로 모든 소스 파일의 문법/타입을 한 줄씩 점검했습니다.
   그래도 실제 실행은 아래 방법으로 사용자 환경에서 최초 실행 후 확인해주세요.

## 실행 방법

```bash
cd memories-maybe
npm install
npm run dev
```

브라우저에서 http://localhost:3000 접속 → 자동으로 샘플 여행("발리 여행")의 일정 화면으로
이동합니다.

프로덕션 빌드:

```bash
npm run build
npm run start
```

### Google Maps 연결 (선택)

API 키 없이도 자체 SVG 기반 지도로 모든 기능(핀 번호, 경로선, 일정↔지도 연동)이 그대로
동작하고, 장소 검색도 내장된 간이 목록(mock DB)으로 동작합니다. 실제 Google Maps +
실시간 장소 검색으로 바꾸려면:

```bash
cp .env.example .env.local
# .env.local 에 아래 값을 채워주세요
# NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=발급받은_키
```

Google Cloud Console에서 **Maps JavaScript API**와 **Places API** 둘 다 사용 설정해야
지도와 검색이 모두 동작합니다. 키가 감지되면 지도는 자동으로 실제 Google Maps로,
일정 추가 화면의 장소 검색도 자동으로 실시간 구글 장소 검색(자동완성)으로 전환됩니다
(`src/lib/googleMapsLoader.ts`가 스크립트를 한 번만 로드해서 지도·검색이 공유합니다).
검색 결과가 없거나 스크립트 로드에 실패하면 조용히 mock 검색으로 대체되고,
그래도 원하는 장소가 없으면 장소명·주소·위도/경도를 직접 입력해서 등록할 수 있습니다.

## 주요 화면 / 기능

- **일정 (`/trip/[id]/schedule`)**: DAY 탭, 세로 타임라인(번호 원 · 시간 · 카드 · 이동거리),
  드래그로 순서 변경(→ 거리/지도 경로 자동 재계산), 일정 카드 ↔ 지도 핀 양방향 하이라이트.
  - **📍 장소 추가**: 트리플처럼 버튼을 누르면 전체 화면으로 전환되어 맛집/관광/숙소
    카테고리 칩 + 검색창 + (지도 API 키가 있으면) 실시간 구글 장소 검색 결과 목록을
    보여줍니다. 원하는 결과를 고르면 확인 화면에서 이름/주소/좌표/시간/카테고리를
    확인·수정하고 작은 지도 미리보기까지 볼 수 있습니다. 검색 결과에 없으면 "직접
    입력하기"로 언제든 수동 등록할 수 있고(API 키가 없거나 검색 실패 시엔 자동으로
    내장 mock 목록으로 대체), 이 화면에서 시간까지 함께 저장됩니다.
  - **📝 메모 추가**: 장소 없이 텍스트만 입력해 그 날 일정 사이에 끼워 넣는 간단한 메모
    항목을 추가할 수 있습니다(트리플의 "메모 추가"와 동일). 지도 핀 번호에는 포함되지
    않고 카드에는 📝 아이콘으로 표시됩니다.
  - **💰 이 장소에 비용 추가**: 일정 목록에서 장소 카드를 선택(하이라이트)하면 카드
    하단에 버튼이 나타나고, 누르면 그 장소가 이미 연결된 상태로 비용 추가 모달이
    열려 바로 지출을 기록할 수 있습니다.
- **지도**: `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` 유무에 따라 Google Maps 또는 자체 SVG 지도
  자동 전환. 모바일은 일정 위 컴팩트 지도, PC는 좌(일정) · 우(지도) 2단 레이아웃.
- **가계부 (`/trip/[id]/expenses`)**: 지출 목록, 기간 필터, "나만보기 비용" 필터, CSV
  가져오기(중복 자동 감지), 지출 추가/수정/삭제, 정산 탭(결제자별 결제액/부담액/최종 정산
  송금액 계산).
- **여행관리 (`/trip/[id]/settings`)**: 여행 정보 수정, 동행자 추가/삭제, 공유 링크 생성.
- **여행 목록 (`/trips`)**: 새 여행 만들기, 온라인(Cloudflare) 여행 만들기/참여하기.
- **온라인 공유 여행 (`/remote/[shareId]/...`)**: 위 화면들과 기능은 동일하지만 데이터가
  브라우저가 아닌 Cloudflare D1 서버에 저장되어, 공유 코드를 아는 다른 사람과 실제로 같은
  데이터를 보고 편집합니다. 배포 방법은 아래 "데이터 저장 / 공유에 대해" 참고.

## CSV 가져오기 동작 방식

`src/lib/csv.ts`가 외부 패키지 없이 RFC4180 규칙을 직접 구현한 CSV 파서입니다. 헤더를
`일차/항목명/카테고리/금액/통화/통화 당 원화/원화 환산/장소/나만보기 비용/결제한 사람/
결제한 사람 수/나눠 낼 사람/나눠 낼 사람 수` 이름으로 자동 매칭하며 컬럼 순서가 달라도
동작합니다. 가져오기 시 (일차, 항목명, 금액, 통화, 장소) 조합으로 고유 키를 만들어 이미
가져온 항목과 중복되면 자동으로 건너뜁니다. 트리플이 CSV 하단에 붙이는 "▼ 통화별 금액" /
"▼ 총 금액" 요약 섹션은 헤더보다 컬럼 수가 적은 행으로 자동 감지해 무시합니다
(`data/okinawa-expenses.csv`가 이 형식을 포함한 실제 예시입니다).

## 정산 로직

`src/lib/settlement.ts` — "나만보기 비용"이 아닌 지출만 대상으로, 각 지출을
`결제한 사람 수`만큼 나눠 결제자에게, `나눠 낼 사람 수`만큼 나눠 분담자에게 배분한 뒤
(결제액-부담액) 잔액이 양수인 사람에게 음수인 사람이 갚도록 최소 송금 횟수로 정산합니다.

## 데이터 저장 / 공유에 대해

기본적으로는 브라우저 `localStorage`에 저장되는 로컬 프로토타입입니다 (`/trip/[id]/...`
경로). 같은 브라우저의 다른 탭에서는 `storage` 이벤트로 즉시 반영되지만, 다른 사람의
기기와는 공유되지 않습니다.

**진짜로 다른 사람과 같은 데이터를 보고 함께 편집하고 싶다면** `worker/` 폴더에 있는
Cloudflare Workers + D1 백엔드를 배포하면 됩니다 (`worker/README-worker.md`에 처음부터
끝까지 단계별로 정리되어 있습니다 — `wrangler login` → D1 생성 → 스키마 적용 →
`wrangler deploy` → `.env.local`에 `NEXT_PUBLIC_API_BASE_URL` 설정, 총 5단계).
배포가 끝나면 `/trips` 화면에 "🌐 온라인으로 공유하기" 카드가 활성화되어 그 자리에서
온라인 여행을 만들거나 공유 코드로 참여할 수 있고, 이 여행들은 `/remote/[공유코드]/...`
경로에서 동작합니다. 실시간 동기화는 완전한 WebSocket이 아니라 **4초 간격 폴링**
방식으로 구현했습니다 (탭이 백그라운드일 땐 자동으로 멈춥니다) — 이 샌드박스 환경에서는
WebSocket/Durable Objects 코드를 실제로 테스트해볼 방법이 없어서, 검증 가능하고 안정적인
폴링 방식을 의도적으로 선택했습니다. 두 사람이 몇 초 시차를 두고 같은 화면을 보게 되는
정도이며, 일정/가계부/동행자 CRUD와 CSV 가져오기, 정산 계산까지 로컬 모드와 동일하게
전부 동작합니다. Worker 백엔드 로직은 Node.js의 내장 `node:sqlite`를 D1 대역으로 삼아
29개 항목의 종단간(end-to-end) 테스트를 통과한 상태이며, 실제 Cloudflare 배포/네트워크
동작 자체는 이 환경에서 실행해볼 수 없어 사용자 환경에서 최초 배포 후 확인이 필요합니다.
로그인 개념은 없고 공유 코드를 아는 사람은 누구나 조회·수정할 수 있는 프로토타입
수준의 공유입니다.

> ⚠️ **이미 배포한 D1 데이터베이스가 있다면**: "메모 추가" 기능 때문에 `schedule_items`
> 테이블에 `kind` 컬럼이 새로 추가되었습니다. 처음 배포하는 경우엔 `schema.sql`에 이미
> 포함되어 있어 신경 쓸 필요 없지만, 이전에 한 번 배포해서 데이터가 이미 들어있다면
> `worker` 폴더에서 아래 1회성 마이그레이션을 실행한 뒤 Worker를 다시 배포해야
> 온라인(공유) 여행에서도 메모가 정상적으로 동기화됩니다.
>
> ```bash
> cd worker
> npx wrangler d1 execute memories-maybe-db --remote --file=./migrate_002_add_kind.sql
> npm run deploy
> ```
>
> (이미 한 번 실행하신 적이 있다면 "duplicate column" 에러가 뜨는데, 이미 적용되어 있다는
> 뜻이라 안전하게 무시하셔도 됩니다. 그리고 아직 Worker/D1 이름을 `memories-maybe-*`로
> 바꾸기 전이라면, 위 명령에서 `memories-maybe-db` 대신 지금 실제로 쓰고 계신 이름을
> 넣어 먼저 실행하셔도 됩니다 — `wrangler.toml`에 지금 적혀 있는 `database_name` 값과
> 똑같이 맞춰서 실행하시면 됩니다.)

## 기술 스택

Next.js 14 (App Router) · TypeScript · React 18 · Tailwind CSS. 상태관리는 별도
라이브러리 없이 React Context + `useReducer` + `localStorage`로 구현했고, 드래그 정렬은
HTML5 Drag & Drop API, CSV 파싱은 자체 구현 파서를 사용해 의존성을 최소화했습니다.
